# Day 7：子 Agent 的任务契约、并发与结果证据

## 学习目标

- 设计包含目标、非目标、输入、写入所有权和独立预算的委派契约。
- 解释并发上限、失败隔离、超时/取消和结果顺序。
- 读懂成功率、证据覆盖率、重复证据率和写入冲突数的含义及局限。

## 前置与项目位置

- 前置：完成 Day 1–6；熟悉 Promise、`AbortSignal` 和数组并发。
- 环境：Node.js 22.18 或更高版本。
- 项目：`examples/minicode/`
- 阅读：`src/subagents.ts`、`tests/subagents.test.ts`。

## 运行

```bash
cd examples/minicode
npm run typecheck
npm test
```

测试使用本地 worker 函数，不会启动模型、后台服务或真实子进程。

## 观察行为

`TaskContract` 描述边界和预算。`SubagentOrchestrator` 先校验合同，再规范化路径，检查相同路径及父子目录所有权冲突；通过后受限并发执行 worker。结果按输入顺序收集。单项失败不抹掉其他结果；预取消不启动 worker，超时及时停止等待。

汇总指标是质量信号而非质量证明：成功率只看状态，证据覆盖率只看成功结果是否有证据，重复率按 evidence URI 统计。证据内容是否真实、充分，仍需人工或专门评估。

## 源码走读：三个任务、并发二、一个失败

给页面审查分配 A（键盘行为）、B（请求取消）、C（性能证据），都只读，`ownedPaths` 为空数组。使用 `new SubagentOrchestrator(2)`。

1. `run()` 复制整批合同，验证 ID 唯一、目标、输入形状、字符串数组和预算；只读任务没有写入冲突。
2. 两个 runner 先领取 A、B。它们共享领取游标，不共享消息历史或预算。
3. B 先抛异常，调度器记录 B 的 `failed`，这个 runner 接着领取 C；A 不因此取消。
4. C 返回 `ok`、非空证据和用量；结果结构及 taskId 校验通过后，写入原始索引 2。
5. A 最后成功。报告仍按 `[A, B, C]` 排列，不是完成顺序 `[B, C, A]`。

报告成功率是 `2/3`。成功结果都必须有证据，所以当前有效成功结果的证据覆盖率为 `1`；这项指标不代表证据正确。若 A、C 各有一条相同 URI，重复证据率为 `(2-1)/2 = 0.5`。有写冲突的整批任务会在执行前拒绝，不会返回一个“冲突数很高但仍成功”的报告。

这个走读用于理解调度顺序；自动测试分别验证部分失败、顺序、峰值和指标，没有模拟真实模型推理。

## 预算必须落在消耗边界

worker 的第三个参数是 `BudgetMeter`。每次模型调用完成或业务步骤完成后调用 `charge(steps, tokens)`，超额会抛异常；不要捕获后继续工作。最终用量取 meter 累计值与 worker 自报值的较大者，避免用较小自报数字掩盖已计量消耗。

这仍不是硬额度计费系统：调度器不能观察任意 worker 内部请求；计量通常发生在消耗之后；不接 meter 只剩返回后的自报检查。生产系统应在发起请求前预留额度、约束供应商最大输出，完成后按实际用量结算。

## 取消、超时和真正的隔离

`AbortSignal` 传播取消意图，`abortable` 负责及时停止调度器等待。已经预取消的父任务不会启动子 worker；运行中取消或截止会记录取消状态。

一个忽略 signal 的函数仍可能继续写文件或发网络请求。及时返回不等于进程被杀死，也不等于真实资源并发永远受限。需要硬隔离时，应让 worker 运行在受控进程/容器并配合终止、权限和幂等机制。`ownedPaths` 同样只是合同检查，不会阻止函数越权写文件。

## 实战任务

现有测试已经覆盖相同路径和父子目录冲突。加练：将 `regressions.test.ts` 的五任务峰值实验改成十任务/并发 `1`，记录开始和结束，检查正常合作 worker 从不重叠；加入一个失败任务，确认排队任务仍能执行且报告顺序不变。

**通过标准：**`npm test` 通过；重叠写入在执行前失败；并发上限为 1 时同一时刻最多一个 worker 运行；已有“部分失败保留成功结果”测试仍通过。

## 故障练习

把两个任务都设为写 `src/shared.ts`，观察调度器在执行前抛出所有权冲突。随后让一个 worker 返回超过 `maxTokens` 的 usage，观察它变成失败结果，而另一任务仍保留自己的状态。

## 验收与面试提问

- 验收：能为一个审查任务写出目标、非目标、输入、ownedPaths、预算和证据 URI，并解释失败结果如何汇总。
- 面试：何时适合并行读，为什么并行写更危险？父任务取消后如何收尾？如何验证子 Agent 的结论，而不只看它自报成功？

## 边界

这里的 worker 是函数，不是独立模型 Agent 或 OS 进程。没有持久任务队列、重启恢复、依赖 DAG、自动重试、跨进程锁或后台通知。路径冲突检查能发现规范化同路径和父子重叠，但不能发现符号链接别名或语义冲突。deadline 会停止等待，不能终止非合作函数。生产调度还需要持久化、隔离和可审计证据。
